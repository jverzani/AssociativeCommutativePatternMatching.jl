    AssociativeCommutativePatternMatching.AssociativeCommutativePatternMatching

    source

    AssociativeCommutativePatternMatching

    This package provides an implementation of the algorithm of Non-linear Associative-Commutative Many-to-One Pattern Matching with Sequence Variables by Manuel Krebber through Chapter 3, referred to as MatchPy.

    A match is a dictionary containing a mapping between wildcard values in the pattern with values in the subject.

    Patterns are specified with expressions and within wildcards are specified by:

    Syntax with predicate note
    ~x ~x::pred a slot variable to match a single argument
    ~!x ~!x a default slot variable to match a single argument
    ~~x ~~x::pred a star variable to match 0, 1 or more arguments
    ~~~x ~~~x::pred a plus variable to match 1 or more arguments

    The variable name is x in each of the above; variable names must be unique within a pattern (so one can't have both a ~x and a ~~x, though the same variable may appear more than once.

    A predicate is a function which is called on a proposed match; unless it returns true (or if it throws an error) the match is rejected. In a quoted pattern, a predicate given by name, as in :(~x::isfoo), is looked up in Main and Base. To use a predicate from another module, write the pattern with @pattern, which evaluates the predicate where the macro is called, or interpolate the function, as in :(~x::$isfoo).

    A default slot variable has default values for the enclosing operations of + (0), * (1), and ^ (the exponent, also 1).

    Matching is against arguments in a function or the function head. Functions may be associative and/or commutative. The MatchPy algorithm allows the separation (as happens with matrix multiplication).

    The pattern f(a, ~x, c) would match f(a,b,c) (with :x => b) but not match f(a,b₁, b₂, c). Whereas f(a, ~~x, c) would match with :x => [b₁, b₂].

    For AssociativeCommutativePatternMatching and associative functions, matches have the function applied to slot variables. So +(a,~x,c) matched against :(+(a, b₁, b₂, c)) would have :x => :(b₁ + b₂).

    Before matching, the arguments of commutative functions in the subject (and in parts of the pattern without wildcards) are put in a standard order. So sin(a + b) + ~x matches sin(b + a) + c, but sin(a - b) + ~x does not match sin(b - a) + c. As a consequence, matched values have commutative arguments in this standard order, e.g. (~x)^(~x) matched against :((x + p)^(x + p)) has :x => :(p + x).

    The primary function is the unexported _eachmatch(pat, sub) function which returns an iterator of matches. The _match(pat, sub) function returns the first value. There are also _rewrite and _replace functions.

    Example

    julia> @time AssociativeCommutativePatternMatching._eachmatch(:(~x + ~y), :(a + b + c));
  0.000071 seconds (60 allocations: 3.000 KiB)

julia> @time AssociativeCommutativePatternMatching._eachmatch(:(~x + ~y), :(a + b)) |> collect
  0.000203 seconds (527 allocations: 26.219 KiB)
2-element Vector{Base.ImmutableDict{Symbol, Any}}:
 Base.ImmutableDict(:x => :a, :y => :b)

julia> @time AssociativeCommutativePatternMatching._eachmatch(:(~x + ~y), :(a + b + c)) |> collect

6-element Vector{Base.ImmutableDict{Symbol, Any}}:
 Base.ImmutableDict(:x => :a, :y => :(b + c))

 Base.ImmutableDict(:x => :(a + b), :y => :c)

 ```

The reduced number of allocations in the first call, is due to the values being returned as a generator. There are additional allocations when iterated by `collect`. The second example shows commutativity being employed, as `+` is assumed to be commutative. As well, `+` is assumed to be associative, so there are 6 matches in the last example, the first of which matches `:(a + (b+c))`.

## Commutative matching

The package also has a matcher which takes commutativity, but not associativity, into account. It is derived from the matcher used for the rule-based methods of [SymbolicIntegration](https://github.com/JuliaSymbolics/SymbolicIntegration.jl). The function `_ceachmatch(pat, sub)` returns a vector of the matches and `_cmatch(pat, sub)` the first match or `nothing`. The macros `@pattern` and `@rule` create patterns and rewriting rules whose guards and right-hand sides are resolved in the calling module; `@acrule` creates a rule which matches with `_match` instead. As with everything else here, they are not exported (SymbolicUtils has macros of these names), so use, e.g., `using AssociativeCommutativePatternMatching: @rule`. The function `_rewrite` rewrites a template using a match.

    julia> AssociativeCommutativePatternMatching._ceachmatch(:(~x + ~y), :(a + b + c)) Base.ImmutableDict{Symbol, Any}[] ```

    Return a vector of the matches of the pattern pat to the subject sub, each a dictionary from wildcard names to their values. The vector is empty if there is no match.

    Unlike _eachmatch, only commutativity of + and * is used, not associativity.

    AssociativeCommutativePatternMatching._replace — Tuple{Any, Any, Pair}

    source 
    _replace([T], ex, args::Pair...)

    Replace parts of an expression with something else.

    Returns a symbolic object of same types as ex

    The replacement is specified using variable => value; these are processed left to right.

    There are different methods depending on the type of key in the the key => value pairs specified:

    • A function call can be replaced by passing in a pair 𝐹 => 𝐹, (e.g. sin=>cos)

    • a variable, say a can be replaced by passing in a pair like a => a^2

    • an expression can be replaced similarly.

    • For wildcard matching, an expression is used on both sides, as in :(cos(~x)) => :(sin(~x)).

    The first three are straightforward. First, for function heads:

    julia> using SymEngine

julia> using AssociativeCommutativePatternMatching; import AssociativeCommutativePatternMatching: _replace

julia> @vars x p
(x, p)

julia> _replace(cos(x) - cos(x^2), cos => sin)
sin(x) - sin(x^2)

    (See below for a hack when the function head is exp.)

    For symbolic variables, we have:

    julia> ex = cos(x) - x*p
-p*x + cos(x)

julia> _replace(ex, x => 2*one(x))
-2*p + cos(2)

julia> _replace(ex, p => 2*one(x))
-2*x + cos(x)

    For symbolic expressions, we have:

    julia> ex = cos(x)^2 + cos(x) + 1
1 + cos(x)^2 + cos(x)

julia> _replace(ex, cos(x) => x)
1 + x + x^2

    Replacements occur only if an entire node in the expression tree is matched:

    julia> u = 1 + x
1 + x

julia> _replace(u + exp(-u), u => x^2)
1 + x + exp(-x^2)

    (As this addition has three terms, 1+x is not a subtree in the expression tree.)

    The last needs more explanation, as there can be wildcards in the expression.

    Wildcards have a naming convention:

    • ~x to match a single part of an expression (possibly all arguments to a function)

    • ~!x like previous, only has a default value when operation is +, *, or ^.

    • ~~x match 0, 1, or more variables

    • ~~x match 1 or more variables

    julia> _replace(cos(pi + x^2), :(cos(pi + ~x)) => :(-cos(~x)))
-cos(x^2)

    julia> ex = log(sin(x)) + tan(sin(x^2))
log(sin(x)) + tan(sin(x^2))

julia> _replace(ex, :(sin(~x)) => :(tan((~x) / 2)))
log(tan((1/2)*x)) + tan(tan((1/2)*x^2))

julia> _replace(ex, :(sin(~x)) => :(~x))
log(x) + tan(x^2)

julia> _replace(x*p, :((~x) * x) => :(~x))
p

    Picture

    The AbstractTrees package can print this tree-representation of the expression ex = sin(x + x*log(x) + cos(x + p + x^2)):

    julia> print_tree(ex;maxdepth=10)
sin
└─ +
   ├─ x
   ├─ *
   │  ├─ x
   │  └─ log
   │     └─ x
   └─ cos              <--
      └─ +             ...
         ├─ x          <--
         ├─ p          ...
         └─ ^          ...
            ├─ x       ...
            └─ 2       ...

    In the _replace command, the wildcard expression :(cos(x + ~x)) looks at the part of the tree that has cos as a node, and the lone child is an expression with node + and child x. The ~x then matchesp + x^2`.

    julia> _replace(sin(x + x*log(x) + cos(x + p + x^2)), :(cos(x + ~x)) => :(sin(~x)))
sin(x + x*log(x) + sin(p + x^2))

    AssociativeCommutativePatternMatching._rewrite — Tuple{Base.ImmutableDict{Symbol, Any}, Any}

    source 
    _rewrite(σ, rhs, [S])
_rewrite(S, σ, rhs)

    Rewrite the template rhs using the match σ.

    If rhs is a function, it is called on σ, as for a rule from @rule.

    If rhs is an expression, its wildcards are replaced by their values. For an Expr subject (S == Expr) the result is an expression. Otherwise each call is evaluated: an operation or other name is looked up in Main, Base and then this package, so to use a function from another module use @rule, or splice the function into the template (:($f(~x))).

    The subject type S is found from the values in σ if not given.

    AssociativeCommutativePatternMatching.@acrule — Tuple{Any}

    source 
    @acrule lhs => rhs

    Create a rule, as @rule does, which matches with the associative-commutative matcher, _match, rather than _cmatch. So + and * are taken to be associative as well as commutative, and ~x + ~y matches a + b + c. A segment (~~x) is replaced by its vector of values.

    Examples

    julia> using AssociativeCommutativePatternMatching: @rule, @acrule

julia> r = @acrule ~x + ~y => (~x) * (~y);

julia> r(:(a + b + c))
:((b + c) * a)

julia> (@rule ~x + ~y => (~x) * (~y))(:(a + b + c)) === nothing
true

    AssociativeCommutativePatternMatching.@pattern — Tuple{Any}

    source 
    @pattern expr

    Create a pattern from expr, as :(expr) would, except each guard of a wildcard (~x::pred, ~~x::pred, ~~~x::pred) is evaluated where the macro is called and spliced into the pattern as a value.

    A guard in a quoted pattern, :(~x::isfoo), is looked up by name in Main and Base when the pattern is matched, so a predicate defined in another package is not found. With @pattern the guard is resolved in the calling module, as is any function a guard such as (u -> isfoo(u)) refers to.

    Values may be interpolated with $, as with a quoted expression.

    Examples

    julia> module Ext
           using AssociativeCommutativePatternMatching: @pattern
           isfoo(x) = x == :a
           pat = @pattern sin(~x::isfoo)
       end;

julia> AssociativeCommutativePatternMatching._ceachmatch(Ext.pat, :(sin(a)))
1-element Vector{Base.ImmutableDict{Symbol, Any}}:
 Base.ImmutableDict(:x => :a)

    AssociativeCommutativePatternMatching.@rule — Tuple{Any}

    source 
    @rule lhs => rhs

    Create a rule which rewrites a subject matching the pattern lhs into rhs, with the wildcards of rhs replaced by their matched values.

    lhs is a pattern, as for @pattern. rhs is Julia code: it is compiled into a function of the match where the macro is called, so functions and variables it refers to are those of the calling module. A segment (~~x) is replaced by its tuple.

    For a symbolic subject rhs is evaluated; for an Expr subject, the matched values are substituted into rhs and an Expr is returned.

    Examples

    julia> using AssociativeCommutativePatternMatching: @rule; using SymEngine

julia> @vars x;

julia> r = @rule (~x)^(~n::isinteger) => (~x)^(~n + 1) / (~n + 1);

julia> r(x^2)
(1/3)*x^3

julia> r(:(x^2))
:(x ^ (2 + 1) / (2 + 1))

julia> r(sin(x)) === nothing
true
