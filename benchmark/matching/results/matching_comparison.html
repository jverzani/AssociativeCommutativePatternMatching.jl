Pattern Matching Comparison

Summary

Each case

A number in a cell is how many matches the matcher found, when more than one. Select a case number or a cell to see the pattern, the subject and each matcher's matches and times.

What stands out

  1. No matcher returns a wrong match. Each match was substituted back into the pattern and the result compared numerically with the subject; of the matches, none disagrees. Two could not be evaluated: MatchMaker's matches for an operation slot (cases 57–58), whose value for F the check cannot call.
  2. Associativity is the largest difference. Only _eachmatch and SymJ let a slot take several terms: they match ~x + ~y against a + b + c six ways (cases 18–22). The others need the pattern and the subject to have the same number of arguments.
  3. Segments are enumerated, or not. For ~~x + ~~y against a + b + c, _eachmatch and _ceachmatch find all 8 splits, as do MatchMaker and SymJ, while SymbolicUtils finds one. SymJ binds a segment in a sum to the sum of its terms (y => a + c) rather than to their list. (_ceachmatch used to give one split too, and under an ordered operation it could split the arguments out of order; MatchMaker's tests found this.) rule2 allows a segment only as the sole argument (+(~~x)), and then binds the whole term rather than its arguments. SymbolicUtils does not accept ~~~y, and rule2 errors on it.
  4. The first match can differ, which is what a rule uses. For (~!a + ~!b*~x)^(~!m) against (1 + x)^4, both ACPM matchers first return a => x, b => 1, x => 1, which is valid, while SymbolicUtils, rule2 and SymJ return a => 1, b => 1, x => x (case 54). In an integration rule, where ~x is bound to the variable beforehand, this does not arise. For ~!a * (~x)^(~!m) against 5x^2, _ceachmatch first returns a => x^2, m => 1, x => 5; _eachmatch keeps only matches using the fewest defaults (case 36). SymJ returns the matches using defaults too: ~!a * ~x against 3x also gives a => 1, x => 3x (cases 30, 32, 34, 36). SymbolicUtils matches (~u)^(~m) against 1/sqrt(x) as u => sqrt(x), m => -1, and the others as u => x, m => -1//2 (case 45).
  5. Most matchers also return role swaps. The ACPM matchers, MatchMaker and SymJ also match the coefficient and the variable the other way round, e.g. a => x, x => 3 for ~!a * ~x against 3x (cases 14, 30, 32, 53). SymbolicUtils' enumeration does not, and rule2 stops at the first match.
  6. A quotient as a product. SymbolicUtils' @rule and MatchMaker do not match (~u)^(~m) * ~v against a / b, or (~u)^(~m) * (~v)^(~n) against a^2 / b^3 (cases 50–51). The others do, by reading the quotient as a * b^-1. All but MatchMaker read 1/x, sqrt(x) and exp(x) as powers.
  7. Guards that throw. Enumerating every match of ~a::isinteger * ~x against 3x makes SymbolicUtils call isinteger(x), which throws (case 40). A rule only uses the first match, a => 3, so this stays hidden. The ACPM matchers and SymJ treat a guard that throws as false. A throw is costly, though: with SymbolicUtils 4.56, isinteger(x) is a MethodError, about 30 µs, and _eachmatch tries a => x before a => 3, so its first match takes µs.
  8. Operation slots. rule2 does not match (~F)(~x) (cases 57–58); the others do.
  9. Speed. For a first match, rule2 takes µs at the median and SymbolicUtils µs. With its pattern compiled, the commutative matcher takes µs, the same as rule2. SymJ takes µs. Without compiling, _cmatch takes µs, and _eachmatch µs ( µs with its pattern compiled; the difference is noise). The slowest cases for _eachmatch are case 40, where a guard throws ( µs), and the product of two binomial powers, case 55, at µs (SymJ µs). Finding every match, the medians are µs for SymbolicUtils, µs compiled, µs for _ceachmatch, µs for SymJ and µs for _eachmatch ( µs compiled). These are close to the first-match medians, as most cases have only one match. The difference shows where there are several: for ~x + ~y + ~z against a + b + c (six matches each), the times are µs compiled, µs for MatchMaker, µs for SymJ, µs for SymbolicUtils, µs for _ceachmatch and µs for _eachmatch. _cmatch stops at the first match, so it rarely reaches a guard that throws: ~a::isinteger * ~x takes µs, while _ceachmatch, finding every match, calls isinteger(x) and takes µs.
  10. Compiling a pattern. compile_pattern works out once what the commutative matcher would otherwise ask of the pattern at every call: which parts are slots, segments or defslots, what each guard is, which operations are commutative and in which order to try their arguments, and which forms of a power apply. The matching then takes the same steps, so the matches are the same, in the same order, on all 62 cases. Most of the time saved comes from not re-reading the pattern, from comparing operations by nameof instead of printing them, from binding a slot without the general match_dict, and from loops specialized on the type of the arguments. @rule compiles its pattern when the rule is made. For _eachmatch, compile_eachmatch only puts the pattern in standard order once, as @acrule does. That is a small part of _eachmatch's time, most of which is in the matching itself, and here it is within the noise of the medians.
  11. MatchMaker. MatchMaker.jl also follows Krebber's algorithm. Its patterns are SymbolicUtils terms with markers, so each @rule pattern here is rewritten: ~x as slot(x), ~~x and ~~~x as segments with at least 0 or 1 terms, ~!x as optional(x) defaulting to the identity of its head, and a guard as a predicate. It returns no wrong matches, and finds all 8 splits of ~~x + ~~y (case 25), as both ACPM matchers do. A slot takes exactly one argument, so it does not match cases 18–22. Building the pattern with SymbolicUtils turns ~x + ~x into 2 * slot(x), which then matches 2a (case 7). It has no views of powers: it does not match 1/x, sqrt(x), exp(x) or a/b as powers (cases 42–48 and 50–51), and an optional is allowed only under + and *, so (~x)^(~!m) is rejected when compiled (cases 34–36, 54, 56). Its first-match median is µs and its all-match median µs. Most of that is building its DAG of the subject on each call, about 1.7–2.5 µs. Its matching on a reused engine (reset!, as its RuleWorkspace does for many rules on one subject) takes about as long as the compiled commutative matcher. matchmaker_corpus.jl runs MatchMaker's own ported test suites through this package; see results/matchmaker_corpus.txt.
  12. SymJ. SymJ's own matcher (SymJ.pattern, then match or eachmatch) reads the same pattern syntax and is associative-commutative, like _eachmatch: it matches 56 of the 62 cases, every case some matcher matches, and returns no wrong match. It is compiled to a typed tree once and matched by backtracking with typed continuations, against SymJ's own terms. Its first-match median is µs, close to rule2 and the compiled commutative matcher, and it stays fast where _eachmatch is slow (case 55 above). Its pattern is put in canonical form first, as any SymJ expression is, so it may mean something else: ~x + ~x is 2*~x, which matches 2a (case 7) and also a + b, with x => a/2 + b/2 (case 60).
  13. Two bugs in _eachmatch were found and fixed in this comparison. On SymbolicUtils terms it threw on 7 of these cases: it compared terms with ==, which is not a Bool for SymbolicUtils, and indexed the arguments with a vector of positions, which SymbolicUtils' argument type does not support.

How this was run

Each pattern is an Expr in the syntax of SymbolicUtils' @rule (~x, ~~x, ~~~x, ~!x, ~x::pred, (~F)(…)), and each subject is built as a SymbolicUtils term from the variables x y z a b c t, so what is matched is the term as SymbolicUtils stores it (a + a is 2a). SymJ's matcher gets the same pattern and the same expression built as a SymJ term. MatchMaker's patterns are rewritten with its markers: ~x as slot(x), ~~x and ~~~x as segments with at least 0 or 1 terms, ~!x as optional(x) defaulting to the identity of its head, and a guard as a predicate. Guards are functions from Base (iseven, isodd, isinteger), which every matcher can find.

For each case and matcher two things are run: the first match, what a rule uses (_match, _cmatch, SymbolicUtils' matcher with a continuation returning its first bindings, rule2's check_expr_r, MatchMaker's and SymJ's match), and every match (collecting _eachmatch, at most ; _ceachmatch; SymbolicUtils' matcher with a continuation that records each match and backtracks, its commutative work budget reset as (r::Rule)(term) does; MatchMaker's matchall; SymJ's eachmatch, which returns the distinct matches). rule2 finds only one match.

A cell is checked when every match (up to 200) was substituted back into the pattern and the result agreed numerically with the subject; not checked when some match could not be evaluated to a number; wrong when one disagreed. No match is not a failure in itself: several cases have no match by design, and the matchers mean different things (only some are associative). An error is an exception from the first match or from enumerating every match.

Times are per call, warm, the best of three batches of at least 2 ms, all in one Julia process. The matchers find different numbers of matches, so the all-match times do not measure the same work. Compare times only within one run.
